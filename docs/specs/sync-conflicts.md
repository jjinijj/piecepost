# sync-conflicts (충돌 처리)

> pm-dev-pipeline 기획서. PM 이 쓰고 개발자가 읽는다. 구현 방법보다 **무엇이 되어야 하는지**를 쓴다.

## 목표
두 기기가 같은 날짜의 우표를 따로 만들거나 고치거나 지워도, 연결된 뒤 두 기기에 **같은 한 장**이 남는다.
어느 쪽이 남는지는 CLAUDE.md "판단 분기"의 규칙(`updatedAt`이 늦은 쪽, 삭제 우선)을 따른다.

## 배경
- `docs/tasks/01-sync-spike.md` 수동 확인 S2·S5·S6, `docs/system-design.md` 3.3 충돌 규칙
- PR #6(CKSyncEngine 연결)에서 남긴 임시 처리 두 곳 (AGENTS.md "남은 작업"의 충돌 처리 항목)
  - `StampSyncEngine.handleFailedSave`의 `serverRecordChanged`: 로그만 남김
  - `SyncChangeApplier.applyReceived`: 로컬에 보낼 변경(`needsUpload`)이 있으면 받은 변경을 건너뜀(`.skippedLocalPending`)
- 지금 상태의 문제: 두 기기가 같은 날짜를 서로 다르게 가지고 있으면 양쪽 다 계속 자기 것을 보내려다 실패하고, 영원히 맞춰지지 않는다

## 완료 기준
판정할 때 하나씩 대조한다.

**보낼 때 충돌 (`serverRecordChanged`)**
1. 로컬 `updatedAt`이 서버 레코드보다 **늦으면**: 서버 레코드의 시스템 필드를 기준으로 로컬 내용을 다시 보내고, 성공하면 서버·로컬 모두 로컬 내용이 된다. 이때 사진을 다시 보낼지는 아래 4번을 따른다
2. 로컬 `updatedAt`이 서버 레코드보다 **이르거나 같으면**: 서버 레코드를 로컬에 반영하고(사진 포함), 로컬의 보낼 변경은 없어진다(`needsUpload == false`, 엔진의 대기 목록에서도 빠짐)
3. 1·2 어느 경우든 같은 레코드가 무한히 다시 보내지는 반복이 생기지 않는다
4. 1에서 로컬이 이겼을 때, 로컬 사진이 서버 사진과 다르면 사진도 함께 보낸다. 즉 사진을 다시 보내지 않아 서버에 **밀린 쪽 사진 + 이긴 쪽 기록**이 섞여 남는 일이 없다
   (예: 기기 A가 사진을 새로 만들고 B가 기록만 고쳤는데 A가 이기면 서버 사진은 A의 사진)

**받을 때 (로컬에 보낼 변경이 있는 상태에서 서버 변경을 받음)**
5. 받은 쪽 `updatedAt`이 로컬보다 늦으면 받은 내용을 반영하고 로컬의 보낼 변경은 없어진다
6. 로컬이 늦거나 같으면 로컬을 유지하고 계속 보낸다. 받은 레코드의 시스템 필드는 저장해 다음 보내기에서 `serverRecordChanged`가 반복되지 않게 한다
   - 2(같으면 서버)와 6(같으면 로컬)은 같은 시각일 때 방향이 다르다. 실제로는 서로 다른 기기의 `updatedAt`이 같을 일이 거의 없으므로 여기서는 결과가 두 기기에서 한 장으로 수렴하기만 하면 된다. 수렴하지 않는 경우가 보이면 보고할 것

**삭제와 수정 (삭제 우선)**
7. 서버에서 지워진 우표를 받으면 로컬에 수정이 있어도 지운다 (PR #6에서 이미 됨. 회귀 없이 유지)
8. 로컬이 삭제 대기(`pendingDeletion`)인데 서버의 수정을 받으면 받은 내용을 반영하지 않고 삭제를 보낸다 (지금 동작 유지)
9. 로컬 수정을 보냈는데 서버에서 이미 지워져 있으면 로컬도 지운다 (PR #6 `unknownItem` 처리 유지)

**밀린 쪽 내용 (2026-11-01 사용자 결정: 버림, 로그만)**
10. 밀린 쪽 기록·사진은 따로 보관하지 않는다. 밀린 로컬 사진 파일은 반영이 끝나면 지운다 (이긴 쪽 파일만 남음)
11. 충돌이 일어나면 로그에 상태만 남긴다. 예: `충돌 serverRecordChanged: 로컬 채택`, `충돌 serverRecordChanged: 서버 채택`, `받기 충돌: 서버 채택`. **날짜·기록 내용·레코드 이름은 남기지 않는다** (불변 규칙 8)

**문서**
12. CLAUDE.md "판단 분기"의 미결정 목록에서 "충돌 시 밀린 쪽 내용 보관·안내 여부"를 빼고, 정해진 내용(버림, 로그만)을 `serverRecordChanged` 줄에 반영한다. `docs/system-design.md` 3.3도 같게 고친다
13. AGENTS.md "남은 작업"에서 충돌 처리 항목을 빼고, "이미 정한 결정"에 밀린 쪽 처리 결정을 더한다. `README.md` 상태 표도 갱신한다

**테스트·검증**
14. 1·2·4·5·6·10에 해당하는 단위 테스트가 있다 (CloudKit 없이 `SyncChangeApplier` 수준에서 확인 가능한 부분)
15. 프로젝트 CLAUDE.md 의 검증 절차를 통과한다 (중간 커밋은 단위 테스트만, 마지막 커밋은 UI 테스트까지 전체)
16. 완료 보고에 수동 확인 S2·S5·S6 체크리스트를 적는다 (자동 테스트로 확인할 수 없으므로 "사용자 확인 필요"로 표시)
