# settings-erase-records (S04 기록 전부 지우기, 레코드 삭제 방식)

> pm-dev-pipeline 기획서. PM 이 쓰고 개발자가 읽는다. 구현 방법보다 **무엇이 되어야 하는지**를 쓴다.

## 목표
사용자가 설정 화면에서 우표 기록을 한 번에 전부 지울 수 있다. 이 기기와 iCloud 에서 지워지고, 같은 iCloud 를 쓰는 다른 기기에는 평소 동기화(레코드 삭제)로 반영된다. 다른 기기가 꺼져 있었어도 켜지면 지워진다.

## 배경
- 첫 시도 `settings-erase-all`(브랜치 `feature/settings-erase-all`, 커밋 13개, PR 안 올림)은 존 `Stamps` 를 통째로 지웠다. 수동 확인(2026-11-04, A=시뮬레이터·B=실기기)에서 두 가지가 실패했다
  - E6: 지운 뒤 첫 우표가 `zoneNotFound` → 다시 예약했지만 CKSyncEngine 이 자동으로 보내지 않음(A=시뮬레이터에서 봄, 실기기 재현은 확인 안 함. 결정 7로 보완했음)
  - E7: B 가 꺼진 동안 A 가 존을 지우고 새 우표로 존을 다시 만들자, B 는 켜진 뒤 존 삭제 알림을 받지 못해 옛 우표가 남음(B=실기기 로그: 가져오기 시작·끝, 받은 변경·존 삭제 줄 없음)
- 사용자 결정(2026-11-04): 존은 남기고 존 안의 우표 레코드를 전부 지우는 방식으로 다시 만든다. develop 에서 새 브랜치
- 레코드 삭제가 두 기기 사이로 전달되는 것은 동기화 시험 S6 에서 확인했다
- `docs/system-design.md` 5장 "기록 전부 지우기" 줄과 그 아래 결정 줄은 이번 방식에 맞게 고친다(완료 기준 12)

## 결정 (사용자)
1. 존 `Stamps` 는 지우지 않는다. 서버의 우표 레코드를 **전부**(이 기기가 아직 받지 못한 레코드 포함) 지운다. 이 기기 로컬에만 있는 우표(올린 적 없음)도 이 기기에서 지운다
2. 순서: iCloud 레코드 삭제 먼저. 전부 성공해야 이 기기를 지운다
3. 부분 실패(일부 레코드만 지워짐): 이 기기 로컬은 지우지 않고 "iCloud에서 일부만 지웠어요." / "인터넷 연결을 확인하고 다시 해 주세요." 를 보여 준다. 이미 지워진 레코드는 평소 동기화로 모든 기기에서 빠진다(이 기기 포함). 다시 누르면 남은 것을 지운다. 하나도 못 지웠으면 기존 "지우지 못했어요." / "인터넷 연결을 확인하고 다시 해 주세요."
4. 다른 기기에 아직 올리지 않은 우표는 지울 목록에 없어 남고, 나중에 올라간다. 1번 확인 창에 안내 한 줄을 더한다. 수정만 대기 중이던 우표는 기존 "삭제 우선" 규칙대로 지워진다
5. 존 삭제 알림 처리는 iOS 설정 > iCloud 저장 공간에서 앱 데이터를 지운 경우(`purged`)를 위해 남긴다: 첫 시도의 결정 1(`deleted`·`purged` 면 로컬 지움, `encryptedDataReset`·그 밖은 유지, 멈춤이면 반영 안 함)과 결정 7('존 없음' 표시 + 저장 때 `.saveZone` 함께 예약). 앱이 존을 지우지 않으므로 첫 시도의 결정 5('내가 지움' 표시)와 지우는 중 받은 존 삭제 보류(`HeldZoneDeletions`)는 가져오지 않는다
6. iCloud 를 쓸 수 없는 상태에서는 버튼 비활성 + 이유(첫 시도와 같음). 용량 부족·오류 상태에서는 누를 수 있음
7. 확인 창 흐름을 자동 테스트하려고 앱에 테스트용 실행 인자를 두지 않는다
8. (구현 중 추가, 사용자) 서버 레코드 삭제가 끝나면 지우는 중 상태로 엔진 가져오기를 한 번 돌려, 이 기기가 한 삭제가 돌아오면 받아 버린 뒤 로컬을 지운다. 지운 직후 같은 날짜로 만든 새 우표가 자기 삭제로 지워지지 않게 하려는 것. 그 가져오기가 실패해도 지우기는 성공으로 보고 로그만 남긴다
9. (구현 중 추가, PM) 목록을 얻을 때 `zoneNotFound` 면 서버 레코드 0개로 보고 성공 처리하고 '존 없음' 표시를 세운다

## 화면·문구
첫 시도와 같다(데이터 구역, 빨간 버튼, 비활성 이유 두 가지, 지우는 중 표시, 지우는 중 닫기 막기, 성공 시 시트 닫음). 바뀌는 것만:
- 확인 1 내용: "우표 N장과 사진이 이 기기와 iCloud, 같은 iCloud를 쓰는 다른 기기에서 모두 지워져요. 다른 기기에서 아직 올리지 않은 기록은 남을 수 있어요."
- 부분 실패 알림: 제목 "iCloud에서 일부만 지웠어요.", 내용 "인터넷 연결을 확인하고 다시 해 주세요."

## 첫 시도에서 가져올 것 / 버릴 것
- 가져옴(코드 검토 후 그대로 또는 고쳐서): `EraseAllAvailability`(+테스트), `SettingsView` 의 데이터 구역·확인 창, `SyncChangeApplier.eraseAllLocal`·`StampFileStore.removeAllFiles`(오류 전파)·`SyncLog.clear`, `ZoneDeletionAction`(결정 5 의 `ignoreOwnErase` 빼고), `ZoneMissingMarker`(+Store), 지우는 중 겹친 보내기·받기 막기(`EraseFence`, `cancelOperations`) — 레코드 삭제에 맞게
- 버림: `modifyRecordZones` 존 삭제, `ZoneEraseOutcome` 의 존 기준 판정(레코드 기준으로 새로), `OwnEraseMarker`(+Store, `own-erase.json`), `HeldZoneDeletions`
- 첫 시도 브랜치는 참고용으로 남긴다(지우지 말 것)

## 완료 기준
1. 설정 화면 "데이터" 구역·버튼·비활성 이유가 첫 시도와 같게 동작한다 (`EraseAllAvailability` 단위 테스트)
2. 확인 창 두 개가 위 문구(확인 1 은 바뀐 문구)대로 뜨고, 취소하면 아무것도 바뀌지 않는다
3. 두 번째 확인 후 서버의 우표 레코드 목록을 서버에서 얻어(이 기기 로컬 목록에만 의존하지 않음) 모두 지운다. 존 `Stamps` 는 지우지 않는다. 화면은 `Sync/` 의 엔진에 요청만 한다 (불변 규칙 4)
4. 서버 레코드를 모두 지웠으면(서버에 레코드가 0개였던 경우 포함) 이 기기의 우표 행·사진 파일·화면 로그를 지운다. 업로드 대기도 지워지고 다시 올라가지 않는다
5. 하나도 못 지웠으면 로컬을 하나도 지우지 않고 "지우지 못했어요." 알림. 일부만 지웠으면 로컬을 지우지 않고 "iCloud에서 일부만 지웠어요." 알림. 다시 누르면 남은 레코드를 지운다. 이미 서버에 없는 레코드(`unknownItem`)는 지운 것으로 본다. 판정은 화면 밖 값 타입에 두고 단위 테스트로 확인한다
6. 지우는 동안과 직후에 겹친 보내기·받기가 지운 우표를 다시 올리거나 다시 넣지 않는다 (첫 시도 `EraseFence` 규칙)
7. 다 지운 뒤 새 우표를 만들면 "지금 보내기" 없이 iCloud 에 올라간다 (존이 그대로라 `zoneNotFound` 가 없어야 함)
8. 다른 기기는 평소 받기로 레코드 삭제를 받아 그 우표를 지운다. 꺼져 있다 켜져도 같다
9. 존 삭제 알림은 결정 5 대로 처리하고(단위 테스트), 그 경로에서도 '존 없음' 표시를 세운다
10. 진단 로그에는 상태·개수·오류 코드만 남긴다. 레코드 이름(날짜가 들어 있음)도 남기지 않는다 (불변 규칙 8)
11. UI 테스트: 동기화를 끈 실행에서 버튼 비활성 + iCloud 이유 문구
12. 문서: `docs/system-design.md` 5장 기록 전부 지우기 줄·결정 줄을 이번 방식으로 고치고, `AGENTS.md` "이미 정한 결정"·"남은 작업", `README.md` 상태 표(와 "구조"에 `Features/Settings/`)를 반영한다. 문서 커밋은 마지막에 따로
13. 프로젝트 CLAUDE.md 검증 절차 통과(중간 `-only-testing:PiecePostTests`, 마지막 전체). 동기화 수정이므로 아래 수동 확인 항목을 보고에 체크리스트로
