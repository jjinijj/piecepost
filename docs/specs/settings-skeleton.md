## 화면 구성 (2026-11-03 사용자 승인)

```
설정                         [닫기]
iCloud 백업
  (아이콘) <상태 제목>
           <상태 설명>        ← 설명이 없는 상태는 줄 없음
정보
  개인정보 처리방침        ›   ← 주소가 없으면 줄을 숨김
  이용약관                ›   ← 주소가 없으면 줄을 숨김
  버전            1.0 (12)    ← CFBundleShortVersionString (CFBundleVersion)
```

상태 문구 (`SyncStatus` 기준):

| SyncStatus | 제목 | 설명 |
|---|---|---|
| `idle` | iCloud에 백업됨 | 없음 |
| `syncing` | 백업하는 중 | 없음 |
| `notStarted` | 확인하는 중 | 없음 |
| `iCloudUnavailable` | iCloud 꺼짐 | 기기에만 저장돼요. iCloud에 로그인하면 백업돼요. |
| `iCloudTemporarilyUnavailable` | iCloud 일시 사용 불가 | 기기에 저장해 두고 잠시 뒤 다시 백업해요. |
| `accountChanged` | 계정 변경됨 | 처음 백업한 iCloud 계정이 아니라 백업을 멈췄어요. 원래 계정으로 돌아오면 이어서 해요. |
| `quotaExceeded` | iCloud 용량 부족 | 기기에는 저장돼 있어요. iCloud 공간을 확보하면 다시 백업해요. |
| `error(code:)` | 백업 오류 | 오류 코드 N (N 은 코드 숫자) |

## 완료 기준
1. 시험 화면 툴바에 톱니 버튼(접근성 이름 "설정")이 있고, 누르면 설정 화면이 시트로 열린다. "닫기"로 닫힌다
2. 설정 화면의 제목은 "설정"이고, "iCloud 백업"·"정보" 두 구역이 위 순서로 보인다
3. "iCloud 백업" 구역은 지금 `SyncMonitor.status` 에 맞는 제목·설명을 위 표 문구 그대로 보여 주고, 상태가 바뀌면 화면을 다시 열지 않아도 바뀐다
4. 상태 → 제목·설명 변환은 화면 밖의 순수 함수(또는 값 타입)에 있고, 표의 8가지 경우를 모두 단위 테스트로 확인한다
5. 설정 화면은 CloudKit 을 직접 부르지 않고 `SyncMonitor` 만 읽는다 (불변 규칙 4). `Features/Settings/` 안의 파일은 `CloudKit` 을 import 하지 않는다
6. 개인정보 처리방침·이용약관 주소는 코드 한 곳(상수)에만 있고 지금은 비어 있다. 비어 있으면 그 줄이 보이지 않는다. 주소가 있으면 누를 때 그 주소를 연다(Safari 또는 앱 안 웹 보기 중 개발자 판단, 고른 이유를 리뷰 파일에 적음). 주소 유무에 따른 표시 여부를 테스트로 확인한다
7. "버전" 줄에 `CFBundleShortVersionString (CFBundleVersion)` 형식으로 앱 버전이 보인다
8. UI 테스트: 시험 화면 → 톱니 → 설정 화면에 "설정"·"iCloud 백업"·"정보"·"버전"이 보이고, 동기화를 끈 실행(`-PiecePostDisableSync`)에서 상태 제목이 "확인하는 중"으로 보인다 → 닫기로 시험 화면에 돌아온다
9. 새 파일은 `Features/Settings/` 에 두고, 파일 이름은 그 안의 주 타입 이름과 같다
10. 진단 로그에 새로 남기는 것이 있다면 상태·오류 코드만 남긴다 (불변 규칙 8)
11. 프로젝트 CLAUDE.md 의 검증 절차를 통과한다 (중간 커밋은 `-only-testing:PiecePostTests`, 마지막 커밋은 UI 테스트 포함 전체)
