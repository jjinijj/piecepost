# sync-send-diagnostics (보내기 진단)

> pm-dev-pipeline 기획서. PM 이 쓰고 개발자가 읽는다. 구현 방법보다 **무엇이 되어야 하는지**를 쓴다.

## 목표
시험 화면에서 보내기를 직접 다시 걸 수 있고, 업로드가 멈췄을 때 **어디서 멈췄는지**를 앱 로그와 맥의 `log show` 로 알 수 있다.

## 배경
- 2026-11-02 사용자 보고: 시뮬레이터에서 우표가 "업로드 대기"로만 남고 올라가지 않아 실기기에 받을 것이 없다. 수동 확인 S1~S9 를 진행할 수 없다
- PM 이 시뮬레이터 로그·앱 데이터를 읽기 전용으로 확인한 결과 (측정)
  - 로컬 우표 1장, `needsUpload == true`, `systemFields == nil`(한 번도 안 올라감). 엔진 상태 파일에 그 레코드의 보내기 예약이 남아 있음
  - 11-01 실행: CKSyncEngine 이 `WillSendChanges` 를 3번 알렸지만 `DidSendChanges`·`SentRecordZoneChanges` 가 없음. 존 저장 작업은 시작만 기록되고 끝난 기록 없음. 레코드 저장 작업은 시작조차 안 됨
  - 11-02 실행: 시작 때 가져오기가 `CKError 36`(Account Temporarily Unavailable) 로 실패. 계정 변경 알림 뒤 "지금 가져오기"는 성공했지만 엔진이 보내기를 다시 시작하지 않음
  - 같은 시각 시뮬레이터 iCloud 계정이 후속 조치 대기(CFU) 상태라는 시스템 로그가 있음
- 앱 쪽 빈틈
  - "지금 가져오기" 만 있고 보내기를 다시 거는 수단이 없다
  - 앱 로그(`SyncLog`)가 OSLog `info` 수준이라 맥에서 `log show` 로 거의 남지 않는다 (11-02 실행에서 "가져오기 끝" 한 줄만 남음). 그래서 우리 코드가 보내기 준비 중 멈췄는지, CloudKit 작업이 멈췄는지 가릴 수 없었다

## 완료 기준
판정할 때 하나씩 대조한다.

**지금 보내기**
1. 시험 화면에 "지금 보내기" 버튼이 있고, 누르면 CKSyncEngine 의 보내기를 직접 시작한다. "지금 가져오기" 와 같은 위치·모양을 따른다
2. 누를 때 로컬의 보낼 변경(`needsUpload`)을 엔진 대기 목록에 다시 넣은 뒤 보낸다. 엔진 상태에 예약이 빠져 있어도 로컬에 보낼 것이 있으면 보내진다
3. 보내기가 오류로 끝나면 로그에 `보내기 실패: CKError <코드>` 처럼 오류 코드가 남는다. 성공하면 기존 `보냄: …` 요약 줄이 남는다
4. 엔진이 없을 때(테스트 실행 등) 누르면 아무 일도 일어나지 않고 앱이 멈추지 않는다

**어디서 멈췄는지 보이게**
5. 다음 시점마다 로그가 한 줄씩 남는다: 보내기 시작(`WillSendChanges`), 보내기 끝(`DidSendChanges`), 보낼 레코드 묶음 요청을 받음(배치 요청 시작)과 그 묶음에 담은 저장·삭제 수, 존 저장 성공·실패
6. "지금 보내기" 를 누를 때와 앱 시작 때 엔진 대기 목록의 **개수만** 로그에 남긴다. 예: `엔진 대기: 저장 1, 삭제 0, 존 0`
7. 앱 시작 때 iCloud 계정 상태를 로그에 남긴다 (`available`·`noAccount`·`restricted`·`temporarilyUnavailable`·`couldNotDetermine` 중 하나, 조회 실패면 오류 코드). **로그만 남기고 동작은 바꾸지 않는다** (계정 상태 처리는 다음 작업)
8. `SyncLog` 로그가 맥에서 `xcrun simctl spawn booted log show --predicate 'subsystem == "com.sisjin.PiecePost"'` 로 `--info` 없이 보인다 (기본 저장되는 수준으로 남김)
9. 새 로그 모두 불변 규칙 8 을 지킨다: 날짜·기록 내용·레코드 이름 없음. 상태·개수·오류 코드만

**테스트·검증**
10. 엔진 대기 목록을 개수 문구로 바꾸는 부분처럼 CloudKit 없이 확인할 수 있는 부분은 단위 테스트가 있다
11. 프로젝트 CLAUDE.md 의 검증 절차를 통과한다 (중간 커밋은 단위 테스트만, 마지막 커밋은 UI 테스트까지 전체)
12. 완료 보고에 사용자가 시뮬레이터에서 확인할 순서를 체크리스트로 적는다: 앱 실행 → "지금 보내기" → 앱 로그 창과 `log show` 에서 무엇을 보면 되는지 (자동 테스트로 확인할 수 없으므로 "사용자 확인 필요")

- 원격 저장소 푸시·PR 생성 (사용자 승인 후 PM 이 진행)
