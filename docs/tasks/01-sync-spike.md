# 작업 01: 동기화 시험(스파이크)

## 목표
실제 화면 없이 Stamp 하나를 CKSyncEngine으로 두 기기 사이에서 주고받을 수 있는지 확인함. 이 구조에서 가장 위험한 부분이므로, 여기서 막히는 점은 설계 변경 제안으로 보고함.

## 시작 전 확인 (사용자가 Xcode·개발자 계정에서 직접 하는 작업)
아래 중 하나라도 확인되지 않으면 코드를 쓰지 말고 사용자에게 질문할 것.
- [ ] Bundle ID 확정
- [ ] Signing & Capabilities에 iCloud 추가, CloudKit 체크, 컨테이너 `iCloud.<Bundle ID>` 생성·선택
- [ ] Background Modes 추가, Remote notifications 체크
- [ ] 시험 기기 2대(실기기 2대 권장, 안 되면 실기기 1대 + 시뮬레이터)에 같은 Apple ID로 iCloud 로그인

## 범위
- 포함
  - SwiftData `Stamp` 로컬 모델(`docs/system-design.md` 3.2)
  - 커스텀 존 `Stamps` 생성
  - `Stamp` ↔ `CKRecord` 변환(3.1 필드 이름 그대로, 레코드 이름 `stamp-YYYY-MM-DD`)
  - CKSyncEngine 연결: 엔진 상태 저장·복원, 계정 변경 이벤트, 받은 변경 반영, 보낸 변경 결과 처리(충돌 포함)
  - 사진 처리 순서(4장)와 photo·thumbnail Asset 업로드
  - 시험용 화면 1개: 우표 목록, 날짜 선택 + 기록 입력 + 사진 선택으로 생성, 기록 수정, 삭제, 동기화 상태와 최근 로그 표시
- 제외
  - 실제 화면(S01~S04) 디자인
  - 운영 서버, 진단 로그 파일·메일 첨부
  - iCloud 상태 배너 UI(상태 값만 화면에 텍스트로 표시)

## 구현 규칙
- CloudKit은 개발 환경만 사용. 운영 스키마 배포 금지
- 충돌 처리는 CLAUDE.md "판단 분기"를 따름. 밀린 쪽 내용 처리는 미결정이므로 로그만 남김
- 파일 위치: 모델 `Data/`, 엔진·변환 `Sync/`, 사진 처리 `Media/`, 시험 화면 `Features/SyncSpike/`

## 수동 확인 항목 (완료 보고에 결과를 체크리스트로 적을 것)
- [ ] S1. 기기 A에서 생성 → 기기 B에 사진·기록 포함해 나타남
- [ ] S2. 기록만 수정 → B에 반영되고, 로그상 photo·thumbnail은 다시 업로드되지 않음
- [ ] S3. 삭제 → B에서도 사라짐
- [ ] S4. A를 비행기 모드로 두고 생성 → 연결 후 자동 업로드됨
- [ ] S5. A·B 둘 다 오프라인에서 같은 날짜로 생성 → 둘 다 연결 후 한 장만 남고, updatedAt이 늦은 쪽 내용임
- [ ] S6. A는 수정, B는 삭제(같은 날짜, 오프라인) → 연결 후 삭제가 남음
- [ ] S7. 앱 삭제 후 재설치 → iCloud에서 우표가 복원됨
- [ ] S8. 앱을 종료했다가 다시 실행 → 엔진 상태가 복원되어 전체를 다시 내려받지 않음(로그로 확인)
- [ ] S9. iCloud 로그아웃 상태에서 생성 → 오류 없이 로컬에 저장되고 상태가 "iCloud 꺼짐"으로 표시됨

2. 빌드·테스트 명령 결과(CLAUDE.md "검증")
3. 발견한 문제와 원인
4. 설계 변경이 필요하다고 보는 점(있으면). 변경은 하지 말고 제안만
